Unit III • Analysis, Design & Implementation

Unit III: Object Oriented Analysis, Design, and Implementation

Complete study guide covering the Object-Oriented Design (OOD) lifecycle, Rumbaugh's 3-Model Integration (OMT), algorithm optimization, control strategies, comparative methodology (SA/SD vs JSD vs OOSD), and the complete translation of OOP concepts into procedural C.

1. Object Oriented Design (OOD) and Object Design

Object-Oriented Design (OOD) is the software engineering phase where analysis models (capturing real-world requirements) are transformed into a technical design specification optimized for implementation.

Two Stages of OOD

  1. System Design (High-Level Design): Defines overall system architecture, subsystem decomposition, database strategy (relational vs object-oriented), hardware/software mapping, concurrency, and global resource management.
  2. Object Design (Low-Level / Detailed Design): Specifies concrete data structures, algorithm implementations, visibility constraints, inheritance adjustments, and precise method signatures for every class.

2. Combining the Three Models (Rumbaugh OMT)

In the Object Modeling Technique (OMT) formulated by James Rumbaugh, a system is modeled across three orthogonal, complementary perspectives:

VISUAL RUMBAUGH OMT THREE-MODEL INTEGRATION
1. Object Model
Static & Structural

Defines WHO exists: classes, attributes, operations, and static relationships.

2. Dynamic Model
Temporal & Behavioral

Defines WHEN actions happen: state transitions, message sequences, and events over time.

3. Functional Model
Computational & Transformational

Defines HOW data transforms: data flows, calculations, algorithms, and inputs/outputs.

Integration & Cross-Validation: The Object Model defines the entities that execute actions; the Dynamic Model dictates when methods execute in response to incoming events; the Functional Model details the algorithmic steps and data mutations performed by those methods.

3. Object Design Activities

3.3 Design Optimization Strategies

Design optimization refines analysis models into high-performance production designs without violating architectural encapsulation:

  • Adding Redundant Associations: Introducing direct pointer links between frequently communicating distant classes to bypass multi-hop navigation paths.
  • Execution Path Tuning: Rearranging computation order so that cheap filter predicates execute before expensive database queries or mathematical operations.
  • Collapsing Derived Classes: Eliminating trivial intermediate subclasses that introduce unnecessary VTable indirection without adding distinct behavioral variation.
  • In-Memory Caching: Storing immutable or infrequently changed derived attributes to avoid redundant disk I/O or recalculation.

4.1 Jackson Structured Development (JSD) In-Depth

Formulated by Michael A. Jackson, JSD is a linear, event-driven software development methodology that models real-world entities through their sequential lifecycle actions over time rather than functional decomposition:

  1. Entity Action Step: Identify real-world entities and the discrete, instantaneous actions they perform or undergo.
  2. Entity Structure Step: Organize identified actions into time-ordered tree structures using Jackson diagram constructs (Sequence, Selection, Iteration).
  3. Initial Model Step: Define the system model as a network of concurrent, communicating sequential processes.
  4. Function Step: Attach output functions and reporting tasks to the core model processes.
  5. System Timing Step: Specify execution scheduling and performance constraints.
  6. Implementation Step: Map concurrent process networks onto available OS threads and procedural code.

3.1 Algorithm Design & Optimization

  • Algorithm Selection: Balance computational time complexity ($O(1)$ vs $O(N)$ vs $O(\log N)$) against memory footprint.
  • Caching Derived Attributes: Store computed values rather than recalculating on every access.
  • Adding Redundant Associations: Add direct navigational links between frequently collaborating classes to eliminate expensive graph traversals.
  • Rearranging Execution Paths: Evaluate high-probability and low-cost boolean terms first in complex conditionals.

3.2 Implementation of Control

  • Procedure-Driven Control: Synchronous, sequential execution stack where control resides in the main program loop.
  • State-Driven / Event-Driven Control: Asynchronous execution where an event pump/dispatcher dynamically selects handlers based on the current state.

3.3 Adjustment of Inheritance & Physical Packaging

  • Factoring Common Behavior: Push shared attributes/methods upward into abstract superclasses.
  • Favoring Composition over Brittle Inheritance: Replace deep inheritance trees with delegation where "is-a" taxonomy is weak.
  • Physical Packaging: Organize cohesive classes into distinct source files, translation units, and shared libraries.

4. Methodological Comparisons: SA/SD vs JSD vs OOSD

Comparison Dimension Structured Analysis / Design (SA/SD) Jackson Structured Development (JSD) Object-Oriented System Design (OOSD)
Primary Focus Functions and Data Flows (DFDs) Entity life-history event sequences over time Autonomous Objects combining state & behavior
Basic Unit Process / Subroutine Sequential Entity Process Class / Object
Decomposition Top-down functional decomposition Event-ordered entity lifecycle modeling Domain entity abstraction and encapsulation
Data & Logic Separated (Processes operate on passive data) Integrated within sequential entity processes Strictly encapsulated together
Reusability Low (code tied to specific flow) Moderate High (Inheritance, Polymorphism, Genericity)
Maintenance Poor (data changes ripple across functions) Moderate Excellent (modular encapsulation barriers)

5. Mapping Object-Oriented Concepts to Non-OOP Languages (C)

When deploying object-oriented designs into non-OOP languages like standard C, developers must explicitly construct OOP mechanisms using data structures and function pointers.

VISUAL C STRUCT MEMORY ALIGNMENT FOR SINGLE INHERITANCE
Base Class: Shape Offset: 0x00
const ShapeVTable* vptr +0 bytes (8B)
Derived Class: Circle (Struct Embedding) Offset: 0x00
Shape base (contains vptr) +0 bytes (8B)
double radius +8 bytes (8B)
* Because Shape base is the first member of Circle, casting (Shape*)&circle points to the exact same memory address.

Complete C Implementation: Classes, Inheritance & VTable Polymorphism

C • Full OOP Mapping Demonstration 
#include <stdio.h>
#include <stdlib.h>

// 1. Forward Declaration of Base Class
struct Shape;

// 2. Virtual Function Table (VTable) Definition in C
typedef struct {
    void (*draw)(const struct Shape* self);
    double (*getArea)(const struct Shape* self);
} ShapeVTable;

// 3. Base Class Representation with VPtr
typedef struct Shape {
    const ShapeVTable* vptr; // Virtual Pointer
} Shape;

// 4. Derived Class: Circle
typedef struct {
    Shape base;        // MUST BE FIRST MEMBER for memory layout alignment
    double radius;
} Circle;

// Member functions for Circle
void Circle_Draw(const Shape* self) {
    const Circle* c = (const Circle*)self;
    printf("Drawing Circle with radius: %.2f\n", c->radius);
}

double Circle_GetArea(const Shape* self) {
    const Circle* c = (const Circle*)self;
    return 3.14159 * c->radius * c->radius;
}

// Static VTable instance for Circle
static const ShapeVTable circle_vtable = {
    .draw = Circle_Draw,
    .getArea = Circle_GetArea
};

// Constructor Function
void Circle_Init(Circle* c, double r) {
    c->base.vptr = &circle_vtable; // Assign VPtr
    c->radius = r;
}

// Polymorphic Client Function
void RenderShape(const Shape* shape) {
    // Dynamic dispatch via VTable lookup
    shape->vptr->draw(shape);
    printf("Calculated Area: %.2f\n\n", shape->vptr->getArea(shape));
}

int main() {
    Circle myCircle;
    Circle_Init(&myCircle, 5.0);

    // Upcasting to Base Pointer is 100% safe due to struct layout
    Shape* shapePtr = (Shape*)&myCircle;
    RenderShape(shapePtr);

    return 0;
}

6. Object Oriented Programming Style & Principles

Object-oriented design focuses on four foundational software quality goals:

  • Reusability: Tested code is reused across multiple subsystems via class libraries, templates, and inheritance.
  • Extensibility: New subclasses and behaviors can be added without modifying existing tested base code (Open/Closed Principle).
  • Robustness: Strong encapsulation and type validation prevent invalid state transitions and undefined behaviors.
  • Programming-in-the-Large: Facilitates large team development through clear modular boundaries and standardized subsystem interfaces.

Unit III Summary

  • Object-Oriented Design (OOD) refines analysis models into high-level System Design and low-level Object Design.
  • Rumbaugh's OMT integrates the Object Model (static), Dynamic Model (state transitions), and Functional Model (computations).
  • Methodological Comparisons: SA/SD separates logic from data; JSD models entity event sequences; OOSD encapsulates data and operations into cohesive classes.
  • Mapping OOP to C: Accomplished by mapping classes to structs, passing an explicit this pointer, embedding base structs first for inheritance, and creating function pointer tables (VTables) for dynamic polymorphism.

Short Answer Questions (2–3 Marks)

2 Marks Differentiate between System Design and Object Design in OOD.

Model Answer:

  • System Design (High-Level): Deals with overall architecture, subsystem decomposition, database choice, concurrency, and hardware allocation.
  • Object Design (Low-Level): Focuses on individual class details: data structures, algorithm selection, method signatures, visibility adjustments, and inheritance refinement.
2 Marks How is single inheritance implemented in procedural C?

Model Answer: Single inheritance is implemented in C by nesting the base class struct as the first member of the derived struct. This guarantees that the memory address of the derived struct matches the memory address of the base struct, allowing safe pointer upcasting.

3 Marks What are the three models in Rumbaugh’s OMT?

Model Answer:

  1. Object Model: Static structure (classes, attributes, relationships).
  2. Dynamic Model: Temporal behavior (state machines, transitions, events).
  3. Functional Model: Computations and transformations (DFDs).

Long Answer Questions (7–10 Marks)

10 Marks Demonstrate how Encapsulation, Inheritance, and Runtime Polymorphism are mapped into C. Provide complete compilable code.

Model Answer Structure:

  1. Explain the mapping principles: structs for classes, function pointer tables for VTables, embedding base structs first for inheritance.

10 Marks Compare Structured Analysis/Structured Design (SA/SD), Jackson Structured Development (JSD), and Object-Oriented System Design (OOSD).

  • Provide a detailed comparative matrix covering: basic abstraction unit, data-logic coupling, decomposition strategy, reusability, and maintenance.
  • Explain why SA/SD suffers from the ripple-effect when requirements evolve.
  • Highlight how OOSD provides superior modularity and extensibility for programming-in-the-large.
