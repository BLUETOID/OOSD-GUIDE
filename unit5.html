Unit V: Objects, Classes, Inheritance, and Polymorphism

Mastery-level reference covering C++ classes, static members, dynamic constructors, deep copy semantics, operator overloading, user-defined type conversions, inheritance models, the diamond problem resolution, and runtime polymorphism via internal VTable/VPtr mechanisms.

1. Classes, Objects, and Static Members

1.1 Static Data Members & Static Member Functions

VISUAL MEMORY MAP: STATIC CLASS MEMBERS VS INSTANCES
Static Data Segment (Shared Class Scope)
ConnectionPool::activeCount = 2
Instance conn1
connId = 101
↑ references static count
Instance conn2
connId = 102
↑ references static count
  • Static Data Member: A single shared variable across all instances, allocated in the static data segment. Must be explicitly defined in global scope outside the class declaration.
  • Static Member Function: Invoked without creating an object instance (Class::func()). Crucial Constraint: Does not possess a this pointer and can only access other static members.
C++ • Static Members Demonstration 
#include <iostream>

class ConnectionPool {
private:
    int id;
    static int activeCount; // Static data member declaration

public:
    ConnectionPool(int connId) : id(connId) {
        activeCount++;
    }

    ~ConnectionPool() {
        activeCount--;
    }

    // Static member function (No 'this' pointer)
    static int getActiveCount() {
        return activeCount;
    }
};

// Explicit global memory definition
int ConnectionPool::activeCount = 0;

int main() {
    ConnectionPool* c1 = new ConnectionPool(1);
    ConnectionPool* c2 = new ConnectionPool(2);
    std::cout << "Active: " << ConnectionPool::getActiveCount() << "\n"; // 2

    delete c1;
    std::cout << "Active after delete: " << ConnectionPool::getActiveCount() << "\n"; // 1
    delete c2;
    return 0;
}

1.2 Constructors, Destructors & Deep Copy Semantics

VISUAL MEMORY DYNAMICS: SHALLOW COPY VS DEEP COPY
Shallow Copy (Memberwise) DANGER
Obj A: ptr ──-> [ Heap: "Hello" ]
Obj B: ptr ──-> [ Heap: "Hello" ]
* Both point to the same memory block. Triggers Double-Free crash on destruction!
Deep Copy (Custom Constructor) SAFE
Obj A: ptr ──-> [ Heap Block 1: "Hello" ]
Obj B: ptr ──-> [ Heap Block 2: "Hello" ]
* Completely distinct heap allocation. Each object manages its own lifetime cleanly.
C++ • Deep Copy Constructor & RAII Destructor 
#include <iostream>
#include <cstring>

class DynamicBuffer {
private:
    char* data;
    int size;

public:
    // 1. Parameterized Dynamic Constructor
    DynamicBuffer(const char* str = "") {
        size = std::strlen(str);
        data = new char[size + 1];
        std::strcpy(data, str);
    }

    // 2. Custom Deep Copy Constructor (Prevents Double Free)
    DynamicBuffer(const DynamicBuffer& other) {
        size = other.size;
        data = new char[size + 1]; // Distinct heap allocation
        std::strcpy(data, other.data);
    }

    // 3. Destructor
    ~DynamicBuffer() {
        delete[] data; // Clean resource deallocation
    }

    void print() const { std::cout << data << "\n"; }
};

2. Operator Overloading and Type Conversion

2.1 Operator Overloading Rules

Enables custom semantics for standard C++ operators. Syntax: ReturnType operator Symbol (Parameters)

Operators that CANNOT be Overloaded in C++:
  1. Scope resolution operator (::)
  2. Direct member access dot operator (.)
  3. Pointer-to-member operator (.*)
  4. Ternary conditional operator (?:)
  5. Size operator (sizeof)
  6. Type identification operator (typeid)
C++ • Overloading Binary + and Stream Insertion << 
#include <iostream>

class Complex {
private:
    double real, imag;

public:
    Complex(double r = 0, double i = 0) : real(r), imag(i) {}

    // Overloading Binary + as Member Function
    Complex operator+(const Complex& o) const {
        return Complex(real + o.real, imag + o.imag);
    }

    // Overloading Prefix ++ (++c)
    Complex& operator++() {
        ++real; ++imag;
        return *this;
    }

    // Overloading Stream << as Friend Function
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        os << c.real << " + " << c.imag << "i";
        return os;
    }
};

int main() {
    Complex c1(3, 4), c2(1.5, 2.5);
    Complex c3 = c1 + c2;
    std::cout << "Result: " << c3 << "\n"; // Output: 4.5 + 6.5i
    return 0;
}

2.2 User-Defined Type Conversion

  • Basic to Class Type: Implemented via single-argument constructors (e.g., Distance d = 500;).
  • Class to Basic Type: Implemented via casting operator functions: operator type() const.

2.4 Type Conversion in C++

In object-oriented C++, type conversions bridge the gap between basic primitive types and user-defined class objects:

  1. Basic Type to Class Type: Implemented via a Single-Argument Parameterized Constructor (e.g. Time(int durationInMinutes)).
  2. Class Type to Basic Type: Implemented via a Casting Operator Function (e.g. operator double() const). The casting operator takes no arguments and has no explicit return type.
  3. Class Type to Another Class Type: Implemented either via a conversion constructor in the destination class or a conversion operator in the source class.
C++ • Class-to-Basic & Basic-to-Class Type Conversion
#include <iostream>

class Distance {
private:
    double meters;

public:
    // 1. Basic to Class Conversion Constructor (meters from double)
    Distance(double m = 0.0) : meters(m) {}

    // 2. Class to Basic Conversion Operator (converts Distance to double kilometers)
    operator double() const {
        return meters / 1000.0;
    }

    void display() const {
        std::cout << meters << " meters\n";
    }
};

int main() {
    // Basic to Class Conversion
    Distance d = 5400.0; 
    std::cout << "Distance Object: ";
    d.display();

    // Class to Basic Conversion
    double km = d; // Invokes operator double()
    std::cout << "Converted to Kilometers: " << km << " km\n";
    return 0;
}

3.4 Exception Handling Keywords & Multiple Catch Blocks

C++ provides structured, type-safe exception handling to decouple error detection from error recovery:

  • try: Encloses a code block that might throw an exception.
  • throw: Signals an abnormal error condition by transmitting an exception object.
  • catch: Catches and processes exceptions matching a specific type parameter.
  • catch(...): The catch-all default handler that intercepts any unhandled exception type.

3.2 The Diamond Problem & Virtual Base Classes

Printer

C++ • Resolving the Diamond Problem with Virtual Base Classes 
#include <iostream>

class PoweredDevice {
public:
    int voltage;
    PoweredDevice(int v = 220) : voltage(v) {}
};

// Virtual base class inheritance eliminates duplicate base copies
class Scanner : virtual public PoweredDevice {
public:
    Scanner(int v) : PoweredDevice(v) {}
};

class Printer : virtual public PoweredDevice {
public:
    Printer(int v) : PoweredDevice(v) {}
};

class Copier : public Scanner, public Printer {
public:
    // Most derived class directly initializes the virtual base class
    Copier(int v) : PoweredDevice(v), Scanner(v), Printer(v) {}
};

int main() {
    Copier c(230);
    // Unambiguous, single copy of voltage in memory
    std::cout << "Copier Voltage: " << c.voltage << "V\n";
    return 0;
}

4. Polymorphism & The Internal VTable / VPtr Mechanics

VISUAL RUNTIME MEMORY LAYOUT: VPTR AND VTABLE LOOKUP
Object Instance in Heap/Stack 0x7ffd98
const void* _vptr ──-> Points to VTable
std::string name +8 bytes
double salary +40 bytes
SalariedEmployee VTable (Static Data) 0x55a820
[0] &SalariedEmployee::calculateSalary() Func Ptr
[1] &SalariedEmployee::printInfo() Func Ptr
[2] &SalariedEmployee::~SalariedEmployee() Destructor

Dynamic Dispatch Mechanism (Late Binding):

  1. Caller invokes basePtr->virtualMethod().
  2. Program dereferences basePtr->_vptr to access the object's runtime VTable.
  3. Finds the function pointer at the designated method index offset.
  4. Indirectly jumps to the resolved function address.
Crucial Exam Concept: Always declare base class destructors as virtual. Otherwise, calling delete basePtr; on a derived object causes undefined behavior and severe memory leaks, as the derived destructor will never execute.
C++ • Comprehensive Runtime Polymorphism Demonstration 
#include <iostream>
#include <vector>

// Abstract Base Class (Interface)
class Employee {
protected:
    std::string name;

public:
    Employee(const std::string& n) : name(n) {}

    // Pure Virtual Function
    virtual double calculateSalary() const = 0;

    // Virtual Function with default implementation
    virtual void printInfo() const {
        std::cout << "Employee: " << name;
    }

    // Virtual Destructor (MANDATORY for memory safety)
    virtual ~Employee() {
        std::cout << "Employee base destroyed: " << name << "\n";
    }
};

class SalariedEmployee : public Employee {
private:
    double monthlyRate;

public:
    SalariedEmployee(const std::string& n, double rate)
        : Employee(n), monthlyRate(rate) {}

    double calculateSalary() const override {
        return monthlyRate;
    }

    void printInfo() const override {
        Employee::printInfo();
        std::cout << " | Type: Salaried | Pay: $" << monthlyRate << "\n";
    }

    ~SalariedEmployee() override {
        std::cout << "SalariedEmployee destroyed\n";
    }
};

int main() {
    std::vector<Employee*> staff;
    staff.push_back(new SalariedEmployee("Alice Smith", 7500.0));

    // Dynamic Binding via VTable
    for (const Employee* e : staff) {
        e->printInfo();
    }

    // Safe polymorphic destruction via virtual destructor
    for (Employee* e : staff) {
        delete e;
    }
    staff.clear();
    return 0;
}

Unit V Summary

  • Classes & Objects encapsulate state; Static members exist at class scope without a this pointer.
  • Constructors & Destructors manage the complete object lifecycle; Deep Copy constructors prevent double-free crashes with dynamic memory.
  • Operator Overloading supports user-defined types; stream operators (<<, >>) are implemented as friend functions.
  • The Diamond Problem in multiple inheritance is resolved using Virtual Base Classes.
  • Runtime Polymorphism is powered by Virtual Functions and the internal VTable / VPtr late-binding lookup mechanism with Virtual Destructors ensuring clean deallocations.

Short Answer Questions (2–3 Marks)

2 Marks Why must a static member function not access the this pointer?

Model Answer: Static member functions belong to the class as a whole and can be called without any object instance (Class::func()). Because no specific instance exists during its invocation, there is no object memory address to pass as the implicit this pointer.

2 Marks Why are Virtual Destructors essential in polymorphic base classes?

Model Answer: When deleting a derived class object through a base class pointer (delete basePtr;), a non-virtual destructor triggers early binding, invoking only the base destructor. Declaring the destructor virtual enables late binding via the VTable, ensuring the derived destructor executes first, preventing memory leaks.

3 Marks List four C++ operators that cannot be overloaded.

Model Answer:

  1. Scope Resolution Operator (::)
  2. Member Access Dot Operator (.)
  3. Pointer-to-Member Operator (.*)
  4. Ternary Conditional Operator (?:)

Long Answer Questions (7–10 Marks)

10 Marks Explain the Diamond Problem in Multiple Inheritance. How do Virtual Base Classes resolve it? Provide complete C++ code.

Model Answer Structure:

  1. Draw the diamond inheritance hierarchy graph (Base -> Derived1, Derived2 -> MostDerived).
  2. Explain the ambiguity caused by duplicate inherited copies of the base class data.
  3. Show how the virtual inheritance keyword ensures a single shared instance of the base class in memory.
  4. Provide complete, working C++ code with PoweredDevice, Scanner, Printer, and Copier.
10 Marks Describe the internal mechanism of Virtual Functions using VTable and VPtr. Explain with object memory layouts and C++ code.

Model Answer Structure:

  • Define early binding (compile-time) vs late binding (run-time dynamic dispatch).
  • Detail the VTable (array of function pointers per class) and VPtr (hidden pointer in each object instance).
  • Draw the step-by-step memory dereference flow when invoking a virtual function through a base pointer.
  • Provide a full code example with an abstract base class, pure virtual functions, and derived implementations.
