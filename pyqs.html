2 Marks • Q1 Describe the significance of modeling in software engineering.

Model Answer:

  • Complexity Management: Decomposes complex real-world systems into cognitively manageable structural and behavioral views.
  • Communication Medium: Provides an unambiguous visual language between technical architects, developers, and non-technical stakeholders.
  • Risk Reduction: Identifies architectural flaws, missing requirements, and integration bottlenecks early in the lifecycle.
  • Blueprint for Construction: Directly guides physical implementation and facilitates automated code generation or reverse engineering.
2 Marks • Q2 Define the conceptual model of UML.

Model Answer: Comprises three foundational pillars:

  1. Building Blocks: Things (Structural, Behavioral, Grouping, Annotational), Relationships (Dependency, Association, Generalization, Realization), and Diagrams.
  2. Rules: Names, Scope, Visibility, Integrity, and Execution.
  3. Common Mechanisms: Specifications, Adornments, Common Divisions (Class/Object), Extensibility Mechanisms (Stereotypes, Tagged Values, Constraints).

2 Marks • Q4 Explain how use case diagrams help in capturing system requirements.

Model Answer:

  • System Boundary: Explicitly defines what is inside the scope of the system vs. external environment.
  • Actor Identification: Identifies all human users and third-party systems interacting with the application.
  • Functional Goals: Models distinct business goals as ellipses, linking them via <<include>> (mandatory sub-routines) and <<extend>> (conditional options).
2 Marks • Q5 Describe the role of inheritance adjustment in design optimization.

Model Answer:

  • Factoring Common Behavior: Pushes identical attributes and methods upward into abstract superclasses.
  • Eliminating Redundant Classes: Collapses classes that do not add distinct behaviors.
  • Favoring Composition: Replaces deep, brittle inheritance hierarchies with delegation.

2 Marks • Q7 Explain the use of the this pointer in C++.

Model Answer: An implicit, constant pointer (ClassName* const this) automatically passed to all non-static member functions holding the memory address of the invoking instance.

  1. Disambiguating Shadowed Members: this->x = x; when parameter names match member names.
  2. Method Chaining: return *this; enabling cascading calls (e.g., obj.setA(1).setB(2);).
2 Marks • Q8 Describe/List the features of object-oriented languages/paradigms.

Model Answer: (1) Abstraction, (2) Encapsulation, (3) Information Hiding, (4) Inheritance, (5) Polymorphism, (6) Dynamic Binding, (7) Message Passing.

2 Marks • Q9 Differentiate between structured approach/procedural and object-oriented approach.
  • Structured: Focuses on functions and data flow (DFDs). Data moves passively across global functions. Top-down functional decomposition.
  • Object-Oriented: Focuses on autonomous objects combining data and methods. Data is private and encapsulated. High reusability and modularity.
2 Marks • Q10 What is UML?

Model Answer: The Unified Modeling Language (UML) is the industry-standard visual modeling language standardized by the Object Management Group (OMG) for specifying, visualizing, constructing, and documenting software system artifacts.

7 Marks • Q1 Explain encapsulation and information hiding. How do they ensure system security and maintainability? Provide a UML example.

Model Answer:

1. Encapsulation: The language packaging mechanism that encloses data members and member functions within a class container.

2. Information Hiding: The design principle of concealing internal data representations and business rules via access specifiers (private, protected).

3. Security & Maintainability: Enforces class invariants (e.g., preventing negative bank balances) and allows internal data structures to change without breaking external client code.

7 Marks • Q31 Explain the architecture of UML (Kruchten's 4+1 View Model).
  1. Use Case View (+1 View): Central view capturing functional requirements for end-users and testers.
  2. Design View (Logical View): Static class and object models for developers.
  3. Process View: Concurrency, threads, and synchronization for system integrators.
  4. Implementation View (Development View): Source files, libraries, and component packages.
  5. Deployment View (Physical View): Hardware devices, nodes, and network topologies.

7 Marks • Q5 Write a C++ program to implement operator overloading for matrix addition and subtraction. 
#include <iostream>
#include <vector>

class Matrix {
private:
    int rows, cols;
    std::vector<std::vector<int>> mat;

public:
    Matrix(int r, int c) : rows(r), cols(c), mat(r, std::vector<int>(c, 0)) {}

    void setElement(int r, int c, int val) { mat[r][c] = val; }

    Matrix operator+(const Matrix& other) const {
        Matrix result(rows, cols);
        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                result.mat[i][j] = this->mat[i][j] + other.mat[i][j];
            }
        }
        return result;
    }

    Matrix operator-(const Matrix& other) const {
        Matrix result(rows, cols);
        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                result.mat[i][j] = this->mat[i][j] - other.mat[i][j];
            }
        }
        return result;
    }

    void display() const {
        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                std::cout << mat[i][j] << "\t";
            }
            std::cout << "\n";
        }
    }
};

int main() {
    Matrix m1(2, 2), m2(2, 2);
    m1.setElement(0,0, 5); m1.setElement(0,1, 8);
    m1.setElement(1,0, 3); m1.setElement(1,1, 4);

    m2.setElement(0,0, 1); m2.setElement(0,1, 2);
    m2.setElement(1,0, 1); m2.setElement(1,1, 1);

    Matrix addRes = m1 + m2;
    Matrix subRes = m1 - m2;

    std::cout << "--- Addition Result ---\n";
    addRes.display();
    std::cout << "--- Subtraction Result ---\n";
    subRes.display();
    return 0;
}

7 Marks • Q15 Develop a C++ program to implement hybrid inheritance. Explain how ambiguity is resolved using virtual base classes. 
#include <iostream>

class Student {
public:
    int rollNumber;
    Student(int r = 0) : rollNumber(r) {}
};

// Virtual base class inheritance eliminates duplicate base copies
class AcademicTest : virtual public Student {
public:
    double part1, part2;
    AcademicTest(int r, double p1, double p2) : Student(r), part1(p1), part2(p2) {}
};

class SportsScore : virtual public Student {
public:
    double sportsScore;
    SportsScore(int r, double s) : Student(r), sportsScore(s) {}
};

class FinalResult : public AcademicTest, public SportsScore {
public:
    FinalResult(int r, double p1, double p2, double s)
        : Student(r), AcademicTest(r, p1, p2), SportsScore(r, s) {}

    void display() const {
        double total = part1 + part2 + sportsScore;
        std::cout << "Roll No: " << rollNumber << " | Total Score: " << total << "\n";
    }
};

int main() {
    FinalResult student1(101, 45.0, 42.0, 9.5);
    student1.display();
    return 0;
}

Roll No: 101 | Total Score: 96.5
