Unit IV: C++ Basics and Functions

Complete, exam-oriented reference manual covering the C++ compilation model, namespaces, modern explicit typecasts, reference semantics, inline functions vs preprocessor macros, function overloading with name mangling, and friend functions.

1. C++ Basics, Overview, and Compilation Model

Developed by Bjarne Stroustrup at Bell Labs in 1979 as "C with Classes", C++ is a statically-typed, multi-paradigm programming language providing direct hardware access with high-level object-oriented abstractions.

1.2 Namespaces

A namespace provides a declarative scope for identifiers (types, functions, variables) to prevent global naming collisions across multiple software libraries.

C++ • Namespace Declarations and Scope Resolution 
#include <iostream>

namespace DatabaseEngine {
    int timeout = 30;
    void connect() { std::cout << "Connected to DB\n"; }
}

namespace NetworkEngine {
    int timeout = 10; // No naming conflict with DatabaseEngine
    void connect() { std::cout << "Connected to Network\n"; }
}

int main() {
    // 1. Explicit Scope Resolution (::)
    DatabaseEngine::connect();

    // 2. Using Declaration (Selective Import)
    using NetworkEngine::connect;
    connect();

    // 3. Using Directive (Imports whole scope)
    using namespace NetworkEngine;
    std::cout << "Network Timeout: " << timeout << "\n";
    return 0;
}

C++ • Dynamic Memory & Array Allocation
#include <iostream>

int main() {
    // Single object allocation
    int* ptr = new int(100);
    std::cout << "Dynamically allocated value: " << *ptr << "\n";
    delete ptr; // Free single object

    // Dynamic array allocation
    int size = 5;
    int* arr = new int[size]{10, 20, 30, 40, 50};
    for (int i = 0; i < size; ++i) {
        std::cout << arr[i] << " ";
    }
    std::cout << "\n";
    delete[] arr; // Free array (MUST use delete[])
    return 0;
}

1.6 Scope Resolution Operator (::) In-Depth

The Scope Resolution Operator :: performs three crucial tasks in C++:

  1. Accessing Global Variables: Accessing a global variable that is shadowed/hidden by a local variable with the same name (::varName).
  2. Defining Member Functions: Defining member functions outside the class declaration body (ReturnType ClassName::funcName()).
  3. Namespace Resolution: Qualifying identifiers within explicit namespaces (std::cout, MyNamespace::var).

1.4 Explicit Typecasting in Modern C++

Cast Operator Evaluation Stage Purpose & Safety Mechanism
static_cast<T>(e) Compile-time Standard numeric conversions and safe upcasting along an inheritance tree.
dynamic_cast<T>(e) Run-time (RTTI) Safe downcasting across polymorphic classes. Returns nullptr for invalid pointer casts.
const_cast<T>(e) Compile-time Adds or removes const and volatile qualifiers from pointers/references.
reinterpret_cast<T>(e) Compile-time Low-level reinterpretation of raw binary bit patterns (e.g., integer to pointer).

2. C++ Functions

2.1 Call and Return by Reference

Call by Reference: Passes an alias (&) directly to the caller's variable, avoiding memory copy overhead and enabling in-place state mutation.

Return by Reference: Returns an lvalue reference to an existing object/array, allowing the function call expression to appear on the left-hand side of an assignment.

C++ • Return by Reference (Lvalue Assignment) 
#include <iostream>

int storage[5] = {10, 20, 30, 40, 50};

// Returning a reference to a static/global array element
int& getStorageElement(int index) {
    return storage[index];
}

int main() {
    // Function call on the LEFT-HAND SIDE of an assignment
    getStorageElement(2) = 999;

    std::cout << "storage[2] is now: " << storage[2] << "\n"; // Output: 999
    return 0;
}

2.2 Inline Functions vs. Preprocessor Macros

An inline function instructs the compiler to expand the function body directly at the call site, eliminating call stack frame overhead while preserving complete type checking and debugging symbols.

Comparison Parameter Preprocessor Macro (#define) Inline Function (inline)
Handling MechanismBlind textual substitution before compilationGenerated code expansion during compilation
Type ValidationCompletely absent (risk of runtime crashes)Strictly enforced by the C++ compiler
Side Effect HazardsVulnerable (e.g., SQR(a++) increments twice)Safe (arguments evaluated once by value/reference)
Debugging SupportInvisible in GDB / debuggersFull symbol table and step-through debugging
Access SpecifiersIgnores private/protected encapsulationRespects class encapsulation boundaries
C++ • Dangerous Side Effects in Macros vs Inline Functions 
#include <iostream>

#define MACRO_SQUARE(x) ((x) * (x))

inline int inlineSquare(int x) {
    return x * x;
}

int main() {
    int a = 3;
    // Expands to ((a++) * (a++)) -> increments 'a' twice!
    int resMacro = MACRO_SQUARE(a++); 
    
    int b = 3;
    // Evaluates 'b++' once, passes 3 by value, increments 'b' once
    int resInline = inlineSquare(b++);

    std::cout << "Macro result: " << resMacro << " (a=" << a << ")\n";   // 12 (a=5)
    std::cout << "Inline result: " << resInline << " (b=" << b << ")\n"; // 9 (b=4)
    return 0;
}

2.3 Function Overloading, Default Arguments & Friend Functions

  • Function Overloading: Functions with the same name differentiated by parameter count or types. Supported internally via Name Mangling (encoding type signatures into symbols). Cannot overload on return type alone.
  • Default Arguments: Must be assigned from right to left in the parameter list.
  • Friend Functions & Classes: Non-member functions granted access to private/protected members using the friend keyword. Friendship is neither inherited nor transitive.
C++ • Friend Function Implementation 
#include <iostream>

class Sensor {
private:
    double reading;

public:
    Sensor(double r) : reading(r) {}

    // Granting external standalone function access to private data
    friend void calibrateSensor(Sensor& s, double offset);
};

void calibrateSensor(Sensor& s, double offset) {
    s.reading += offset; // Direct private access
    std::cout << "Calibrated Reading: " << s.reading << "\n";
}

int main() {
    Sensor s(25.0);
    calibrateSensor(s, 2.5);
    return 0;
}

Unit IV Summary

  • Compilation Model traverses Preprocessing, Compilation, Assembly, and Linking stages.
  • Namespaces eliminate global naming collisions using scope resolution (::) and using directives.
  • Explicit Casts: static_cast (standard conversions), dynamic_cast (safe polymorphic downcasting), const_cast (cv-qualifiers), reinterpret_cast (low-level reinterpretation).
  • Call and Return by Reference enable in-place modification and lvalue expressions.
  • Inline Functions eliminate call overhead with strong compiler type safety, avoiding macro side-effect hazards.
  • Friend Functions allow designated external functions access to internal private class members.

Short Answer Questions (2–3 Marks)

2 Marks Differentiate between static_cast and dynamic_cast in C++.

Model Answer:

  • static_cast: Evaluated at compile-time for standard data conversions and non-polymorphic pointer upcasting.
  • dynamic_cast: Evaluated at runtime using RTTI for safe downcasting along polymorphic inheritance trees. Returns nullptr if the cast is invalid.
2 Marks What is Name Mangling in C++? Why is it required?

Model Answer: Name mangling (decoration) is the compiler technique of appending parameter type signatures to function identifiers (e.g., _Z3addii). It is required by linkers to differentiate overloaded functions sharing the same name.

3 Marks State the rules governing Default Arguments in C++ functions.

Model Answer:

  1. Default values must be supplied from right to left (trailing parameters first).
  2. Default arguments must be specified in the function prototype/declaration, not in both prototype and definition.
