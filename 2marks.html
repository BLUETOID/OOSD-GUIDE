Unit 1: Introduction to Object Orientation & UML (2 Marks)

U1-Q01 Define Object identity with example. [2020-21]

Definition: Object identity is the inherent property of an object that distinguishes it from all other objects in the universe, regardless of its state, values, or class type. Identity is immutable and persists throughout the object's entire lifespan.

Example: In C++, two instances Account a1(101, 500); and Account a2(101, 500); possess identical attribute values, but have distinct identities because they reside at unique memory addresses (&a1 != &a2). In databases, identity is enforced via primary keys (e.g., UUID).

U1-Q02 List the features of Object-oriented paradigms. [2020-21]

The foundational features characterizing the Object-Oriented Paradigm are:

  • Encapsulation: Packaging data and operations into a single cohesive class unit.
  • Data Abstraction & Information Hiding: Exposing essential interface contracts while concealing implementation mechanics.
  • Inheritance: Reusing and extending state and behavior across hierarchical class relationships.
  • Polymorphism: Dynamic message dispatch allowing uniform invocation across distinct concrete types.
  • Generosity (Genericity): Parameterizing algorithms and structures with generic data types.
U1-Q03 What is information hiding? [2021-22]

Definition: Information hiding (David Parnas Principle) is the software design principle of shielding internal implementation decisions, internal data representations, and volatile algorithms from external client modules.

Significance: Clients interact exclusively through stable public method signatures (contracts). This ensures system security, prevents illegal state corruption, and allows internal implementations to be refactored without breaking client code.

U1-Q04 Define data encapsulation. Give example. [2022-23]

Definition: Data encapsulation is the mechanism that binds together data variables (state) and the member functions (behavior) that manipulate them into a single self-contained syntactic unit, restricting direct access from outside.

class BankAccount {
private:
    double balance; // Encapsulated private state
public:
    void deposit(double amt) { if (amt > 0) balance += amt; }
    double getBalance() const { return balance; }
};
U1-Q05 Define generosity. [2022-23]

Definition: Generosity (commonly termed genericity or generic programming) is the ability to define software modules (classes, functions, algorithms) parameterized by data types, without binding them to concrete types at declaration time.

Example: C++ templates allow a single Stack<T> class definition to instantiate type-safe stacks for integers (Stack<int>), strings (Stack<string>), and custom objects with zero runtime overhead.

U1-Q06 List the features of object oriented language. [2022-23]

An object-oriented language provides direct syntax and runtime support for:

  1. Class and Object constructs (state + behavioral encapsulation).
  2. Access specifiers (public, private, protected) enforcing information hiding.
  3. Inheritance hierarchies (single, multiple, multilevel).
  4. Polymorphism (overloading and dynamic virtual method tables).
  5. Automatic object initialization and destruction (constructors/destructors, RAII).
  6. Dynamic memory allocation and type-safe exception handling.
U1-Q07 Describe the features of object-oriented languages? [2023-24]

Object-oriented languages are characterized by: (1) Modularity via autonomous classes; (2) Message Passing as the sole medium for object communication; (3) Late Binding where function addresses are dynamically looked up at runtime via VTables; (4) Extensibility allowing new subclasses to be introduced without modifying legacy client code (Open-Closed Principle); and (5) Reusability through class libraries, generic templates, and inheritance.

U1-Q08 What is UML? [2023-24]

Definition: The Unified Modeling Language (UML) is a standardized, general-purpose graphical modeling language maintained by the Object Management Group (OMG). It is designed for visualizing, specifying, constructing, and documenting the structural, behavioral, and architectural artifacts of software-intensive systems.

U1-Q09 Describe the significance of modeling in software engineering. [2024-25]

Modeling provides a disciplined blueprint of software systems prior to expensive implementation. Its significance includes:

  • Complexity Management: Abstraction filters irrelevant implementation noise, highlighting architectural relationships.
  • Stakeholder Communication: Unifies technical architects, programmers, and domain business clients under standard graphical semantics.
  • Risk Mitigation: Uncovers design flaws, bottlenecks, and missing requirements early in the lifecycle.
  • Code Synthesis & Verification: Serves as a direct blueprint for automatic code generation and test harness derivation.
U1-Q10 Define the conceptual model of UML. [2024-25]

Definition: The conceptual model of UML comprises three core foundational components:

  1. UML Building Blocks: Things (Structural, Behavioral, Grouping, Annotational), Relationships (Dependency, Association, Generalization, Realization), and Diagrams (Structural and Behavioral).
  2. Rules: Syntactic and semantic rules governing well-formed models (names, scope, visibility, integrity, execution).
  3. Common Mechanisms: Specifications, Adornments, Common Divisions, and Extensibility Mechanisms (Stereotypes, Tagged Values, Constraints).
U1-Q11 State the principles of modeling. [2025-26]

The four fundamental principles of modeling (Booch, Rumbaugh, Jacobson) are:

  1. The choice of what models to create has a profound influence on how a problem is attacked and how a solution is shaped.
  2. Every model may be expressed at different levels of precision.
  3. The best models are connected to reality.
  4. No single model is sufficient. Every non-trivial system is best approached through a small set of nearly independent views.
U1-Q12 Mention any two advantages of object-oriented approach. [2025-26]
  1. Modular Reusability and Maintainability: Objects act as autonomous components. Code can be extended via inheritance and composition without modifying or destabilizing validated existing modules.
  2. Direct Domain Mapping & Fault Isolation: Software entities directly mirror real-world domain concepts. Encapsulation confines data corruption and operational faults strictly within the class boundary.
U1-Q13 What is encapsulation in object-oriented design? [2025-26]

Definition: In object-oriented design, encapsulation is the architectural technique of co-locating data attributes and their associated behavioral operations inside a unified boundary (the class), while enforcing access restrictions via private/protected boundaries to prevent arbitrary external state mutation.

Unit 2: Basic Structural, Behavioural & Architectural Modeling (2 Marks)

U2-Q01 Define and Differentiate Link and Association with example. [2020-21]

Link: A physical or conceptual connection between specific object instances at runtime (e.g., john:Employee ——— itDept:Department).

Association: A class-level structural abstraction describing a group of links with common semantics, roles, and multiplicity constraints (e.g., Employee (1..*) ————— (1) Department).

Core Distinction: A link is an instance of an association, mirroring the exact relationship an object has to a class.

U2-Q02 Define and Differentiate Generalization and Inheritance with example. [2020-21]

Generalization: The conceptual/modeling relationship where a specialized classifier (subclass) shares the structure and behavior of a more general classifier (superclass) — an "is-a" relationship (e.g., Dog is a Mammal).

Inheritance: The programming language implementation mechanism that executes generalization by passing down data fields and member functions to derived types (e.g., class Dog : public Mammal).

Distinction: Generalization is an architectural analysis concept; inheritance is its syntactic code implementation.

U2-Q03 How it is different from multiple inheritance and modelled by using nested generalization? [2020-21]

Multiple Inheritance: A subclass directly inherits from two or more distinct superclasses simultaneously, potentially triggering ambiguity (the Diamond Problem).

Nested Generalization: Decomposes complex classification taxonomies into hierarchical, orthogonal single-inheritance tiers using discriminators (e.g., classifying Vehicle first by PropulsionType [Land, Water] and then sub-classifying by UsageType [Commercial, Private]). This eliminates the syntactic ambiguity and VTable overhead of multiple inheritance.

U2-Q06 List the features of Component Diagram. [2022-23]

Key features of a UML Component Diagram include:

  • Models executable binaries, software libraries (DLLs, JARs), database schemas, and source code files.
  • Visualizes Provided Interfaces using lollipop notation (—○) specifying services the component publishes.
  • Visualizes Required Interfaces using socket notation (—() specifying external services needed.
  • Captures high-level software modularity, packaging dependencies, and component contracts.
U2-Q07 Explain the existence of swimlanes in activity diagram. [2022-23]

Definition & Role: Swimlanes partition an activity diagram into vertical or horizontal column zones. While standard activity diagrams depict what actions occur sequentially or concurrently, swimlanes explicitly identify who (which department, actor, subsystem, or business role) is responsible for executing each action. This establishes accountability across cross-functional business processes.

U2-Q08 Describe generalization. [2023-24]

Definition: Generalization is a taxonomic relationship between a general classifier (parent/superclass) and one or more specific classifiers (child/subclasses). The child inherits all attributes, operations, and relationships of the parent, and may add new features or override inherited operations (polymorphism). Rendered as a solid line with a hollow triangular arrowhead pointing to the superclass.

U2-Q10 Explain how use case diagrams help in capturing system requirements. [2024-25]

Use case diagrams capture functional requirements by:

  • Establishing System Boundaries: Separates internal system services from external actors (users, devices, external software).
  • Goal-Oriented Specification: Models the discrete business value delivered to actors without committing to premature user interface or database designs.
  • Scoping & Verification: Acts as an agreement baseline between clients and developers, providing direct traceability for integration acceptance test suites.
U2-Q11 Define association and aggregation. [2025-26]

Association: A general bi-directional structural relationship specifying that instances of one class are connected to and interact with instances of another (e.g., Patient books Appointment).

Aggregation: A specialized form of association denoting a "whole-part" relationship where the "part" can exist independently of the "whole" (weak lifecycle binding). Rendered with a hollow diamond at the whole class end (e.g., Department <>———— Professor; if the department disbands, the professors continue to exist).

Unit 3: Object Oriented Analysis, Design & Programming Style (2 Marks)

U3-Q01 Define and differentiate Procedural and OOP with example. [2020-21]

Procedural Programming: Focuses on sequential algorithms and step-by-step procedures manipulating passive data structures. Example: C program calling calculateArea(&rect) with global variables.

Object-Oriented Programming (OOP): Focuses on autonomous entities encapsulating both internal state and behavior. Example: C++ program invoking rect.calculateArea() via message passing.

Distinction: Procedural separates functions from data; OOP tightly integrates them, preventing unauthorized data corruption.

U3-Q03 What are the three models in OMT? [2023-24]

Rumbaugh's Object Modeling Technique (OMT) defines:

  1. Object Model: Captures static structure, classes, attributes, operations, and associations (UML Class Diagram).
  2. Dynamic Model: Captures time-ordered control, states, transitions, and reactive events (UML Statechart/Interaction Diagram).
  3. Functional Model: Captures data transformations and algorithmic computations (Data Flow Diagram - DFD).
U3-Q04 What do you mean by the optimization of design? [2023-24]

Definition: Design optimization is the phase within Object Design where the analysis models (which focus purely on logical correctness and domain fidelity) are re-engineered to satisfy real-world performance constraints, including throughput, memory footprint, response time, and computational efficiency.

Primary Tactics: Caching derived attributes, introducing redundant associative links for fast traversal, optimizing algorithmic complexity, and rearranging execution paths.

U3-Q05 Describe the role of inheritance adjustment in design optimization. [2024-25]

Inheritance adjustment optimizes class hierarchies during detailed design through:

  • Factoring Common Behavior: Consolidating identical attributes and methods discovered across disparate subclasses into a shared abstract base class to eliminate duplicate code.
  • Flattening Redundant Superclasses: Collapsing intermediate trivial abstract layers that add VTable dispatch indirection without distinct behavioral variance.
  • Converting Misused Inheritance to Composition: Replacing "is-a" with "has-a" when only partial functionality is needed, preventing fragile base class coupling.
U3-Q06 How are classes translated into data structures? [2025-26]

During object design and implementation, abstract classes are mapped to physical programming constructs:

  • Class Entities: Translated into C/C++ structs or class records holding field offsets in memory.
  • One-to-One Associations: Mapped to direct object pointers or reference handles.
  • One-to-Many / Many-to-Many Associations: Mapped to dynamic collection data structures (arrays, linked lists, balanced binary trees, or hash tables based on query frequency).
  • Polymorphic Methods: Mapped to function pointer dispatch tables (VTables).
