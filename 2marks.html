Q1 • 2 Marks Describe the significance of modeling in software engineering.

Model Answer: Modeling creates abstract visual representations of a system to understand, design, and validate software before coding.

  • Complexity Management: Decomposes complex real-world problems into manageable structural and behavioral views.
  • Clear Communication: Provides an unambiguous visual language between technical architects, developers, and clients.
  • Early Risk Mitigation: Exposes architectural flaws, missing requirements, and integration bottlenecks early in the lifecycle.
  • Construction Blueprint: Guides implementation and facilitates automated code generation or reverse engineering.
Q2 • 2 Marks Define the conceptual model of UML.

Model Answer: The conceptual model of UML comprises three foundational pillars:

  1. Building Blocks: Things (Structural, Behavioral, Grouping, Annotational), Relationships (Dependency, Association, Generalization, Realization), and Diagrams.
  2. Rules: Syntactic and semantic rules governing Names, Scope, Visibility, Integrity, and Execution.
  3. Common Mechanisms: Specifications, Adornments, Common Divisions (Class vs Object, Interface vs Implementation), and Extensibility (Stereotypes, Tagged Values, Constraints).

Q4 • 2 Marks Explain how use case diagrams help in capturing system requirements.

Model Answer:

  • System Boundaries: Delineates internal system scope from the external environment.
  • Actor Identification: Identifies all direct human roles and external systems interacting with the application.
  • Functional Behavior: Captures discrete user goals as ellipses, using <<include>> (mandatory sub-routines) and <<extend>> (conditional options).
  • Testing Baseline: Serves as the direct input for creating user acceptance test suites.
Q5 • 2 Marks Describe the role of inheritance adjustment in design optimization.

Model Answer: In the Object Design phase, inheritance hierarchies are restructured to improve efficiency and maintainability:

  • Factoring Common Attributes & Methods: Pushing identical members upward into abstract base superclasses.
  • Eliminating Redundant Leaf Classes: Collapsing classes with trivial differences into single parameterized classes.
  • Replacing Inheritance with Delegation: Replacing deep, brittle inheritance coupling with object composition where an "is-a" taxonomy is weak.

Q7 • 2 Marks Explain the use of the this pointer in C++.

Model Answer: The this pointer is an implicit, constant pointer (ClassName* const this) passed to all non-static member functions, holding the memory address of the invoking instance.

  • Disambiguating Shadowed Members: this->val = val; when parameter names match member variables.
  • Method Chaining: Returning *this by reference (e.g. return *this;) allowing cascading calls like obj.setA(5).setB(10);.
Q8 • 2 Marks Describe/List the features of object-oriented languages/paradigms.

Model Answer:

  1. Abstraction: Representing essential features while hiding background details.
  2. Encapsulation: Bundling data and methods into a single class container.
  3. Information Hiding: Restricting direct state access via private/protected specifiers.
  4. Inheritance: Reusing and extending existing class definitions in a taxonomic hierarchy.
  5. Polymorphism: Enabling a single interface to exhibit multiple runtime behaviors.
  6. Dynamic Binding: Resolving method addresses dynamically at runtime via VTables.

Q10 • 2 Marks What is UML?

Model Answer: The Unified Modeling Language (UML) is an industry-standard visual modeling language standardized by the Object Management Group (OMG) in 1997. It is used to specify, visualize, construct, and document the software artifacts of object-oriented systems by unifying the Booch, OMT (Rumbaugh), and OOSE (Jacobson) methodologies.

Q11 • 2 Marks Describe generalization.

Model Answer: Generalization is a taxonomic "is-a" relationship between a general class (superclass/base class) and a specialized class (subclass/derived class). The specialized class inherits all attributes, operations, and relationships of the general class, and can add new members or override inherited operations. Represented in UML by a solid line with a hollow triangular arrowhead pointing to the superclass (──────▷).

Q12 • 2 Marks What are the three models in OMT?

Model Answer: In James Rumbaugh’s Object Modeling Technique (OMT), a system is characterized across three orthogonal perspectives:

  1. Object Model: Static structural blueprint (Classes, Attributes, Operations, Relationships).
  2. Dynamic Model: Temporal behavior and state changes over time (State Machines, Events).
  3. Functional Model: Computational data transformations (Data Flow Diagrams, Functions).
Q13 • 2 Marks What do you mean by the optimization of design?

Model Answer: Design optimization is the process of refining object design models to improve execution speed, minimize memory usage, and reduce communication latency without destroying modularity. Key techniques include: adding redundant direct associations to eliminate graph traversals, caching expensive derived attributes, and rearranging conditional execution paths.

Q14 • 2 Marks Write a C++ program to calculate the value of sin(x). 
#include <iostream>
#include <cmath>

// Calculates sin(x) using Taylor Series: x - x^3/3! + x^5/5! - x^7/7! ...
double calculateSin(double degrees, int terms = 10) {
    double rad = degrees * (M_PI / 180.0); // Convert degrees to radians
    double sum = 0.0, term = rad;
    for (int i = 1; i <= terms; i++) {
        sum += term;
        term = -term * rad * rad / ((2 * i) * (2 * i + 1));
    }
    return sum;
}

int main() {
    double deg = 30.0;
    std::cout << "sin(" << deg << ") = " << calculateSin(deg) << "\n"; // ~0.5
    return 0;
}
Q15 • 2 Marks Explain typecasting in C++.

Model Answer: Typecasting is the explicit or implicit conversion of a variable from one data type to another. Modern C++ provides four explicit cast operators:

  • static_cast<T>(e): Standard compile-time numeric and pointer conversions.
  • dynamic_cast<T>(e): Runtime polymorphic downcasting verified via RTTI.
  • const_cast<T>(e): Adds or strips const/volatile qualifiers.
  • reinterpret_cast<T>(e): Low-level bit-pattern reinterpretation (e.g. pointer to integer).
Q16 • 2 Marks Differentiate between public and private member function.
  • Public Member Function (public:): Accessible from any external function or scope. Represents the public interface and contract of the class.
  • Private Member Function (private:): Accessible only by other member functions of the same class (and declared friend functions). Used for internal helper routines and algorithms.
Q17 • 2 Marks Explain static data and static function member.
  • Static Data Member: A single shared class variable allocated in the static data segment across all object instances. Must be defined in global file scope outside the class.
  • Static Member Function: A class-level function callable without an object instance (Class::func()). It has no this pointer and can only access other static members.
Q18 • 2 Marks Define data encapsulation. Give example.

Model Answer: Data Encapsulation is the mechanism of bundling data members (attributes) and member functions (behavior) into a single physical unit (a class).

class Rectangle {
private:
    double length, width; // Encapsulated private state
public:
    Rectangle(double l, double w) : length(l), width(w) {}
    double getArea() const { return length * width; } // Encapsulated operation
};
Q19 • 2 Marks Define generosity.

Model Answer: Generosity (also known as Genericity) is the object-oriented capability to define classes, algorithms, and data structures with parameterized types. This enables code reuse across arbitrary data types with compile-time type safety and zero runtime overhead. Implemented in C++ via Templates (e.g. template <typename T>).

Q21 • 2 Marks Explain the existence of swimlanes in activity diagram.

Model Answer: Swimlanes are vertical or horizontal partitions in an Activity Diagram that assign responsibility for actions to specific organizational departments, roles, or software subsystems. They make it explicit not just what actions occur, but who or which subsystem class executes each step in a workflow.

Q22 • 2 Marks Describe the term enum.

Model Answer: An enum (enumeration) is a user-defined type consisting of a set of named integral constants.

  • Unscoped enum: Exports names to the enclosing scope and implicitly converts to integers.
  • Scoped enum class (C++11): Strongly typed, prevents name pollution (accessed via Color::RED), and disallows unsafe implicit integer conversions.
Q23 • 2 Marks Define friend function with example / What is its use in C++?

Model Answer: A friend function is a non-member external function granted access to the private and protected members of a class using the friend keyword.

class Point {
private:
    int x, y;
public:
    Point(int a, int b) : x(a), y(b) {}
    friend void printCoords(const Point& p); // Friend declaration
};

void printCoords(const Point& p) {
    std::cout << "(" << p.x << ", " << p.y << ")\n"; // Direct private access
}
Q24 • 2 Marks Give a brief description about function overriding.

Model Answer: Function Overriding occurs when a derived class redefines a member function of its base class with the exact same name, parameter types, and return type. In C++, dynamic runtime overriding requires declaring the base function as virtual, enabling dynamic dispatch via the VTable.

Q25 • 2 Marks Differentiate between link and association / Define with example.
  • Association: An abstract structural relationship between two classes describing possible connections (e.g. Class Student $\longleftrightarrow$ Class Course).
  • Link: A concrete physical connection between two specific object instances in memory at runtime (e.g. alice : Student has a link to cs101 : Course).
  • Analogy: Association is to Link what a Class is to an Object.
Q26 • 2 Marks What is an abstract class? Is it possible that an abstract class is inherited by another class?

Model Answer: An Abstract Class is a class that contains at least one **Pure Virtual Function** (virtual void func() = 0;). It cannot be instantiated directly and serves as an interface contract.

Inheritance: Yes, abstract classes are explicitly designed to be inherited. If a derived subclass implements all pure virtual functions, it becomes a concrete instantiable class; otherwise, it remains abstract.

Q28 • 2 Marks When do we use the protected visibility specifier to a class member?

Model Answer: The protected specifier is used when a class member must be hidden from external public access (preventing unauthorized modification) while still being directly accessible to **derived subclasses** in an inheritance hierarchy.

Q29 • 2 Marks When will you make a function inline? Why?

Model Answer: A function is made inline when it is **small (1 to 4 lines), simple, and executed frequently** inside performance-critical loops.

Why: It eliminates function call overhead (call stack frame creation, register push/pop, jump instructions) by expanding code directly at the call site with full compiler type checking.

Q30 • 2 Marks Define constructor and destructor. Why do we use a destructor in a program?
  • Constructor: A special member function sharing the class name that initializes object state upon creation.
  • Destructor: A member function prefixed with a tilde (~ClassName()) executed automatically when an object lifetime ends.
  • Why use Destructors: To release allocated system resources (freeing heap memory with delete, closing file descriptors, releasing locks) adhering to the RAII principle.
Q31 • 2 Marks What is the use of Scope resolution operator?

Model Answer: The Scope Resolution Operator (::) is used to:

  1. Access global variables when shadowed by local variables (::globalVar).
  2. Define member functions outside the class declaration (void MyClass::method()).
  3. Access static members of a class (MyClass::staticMember).
  4. Disambiguate namespace symbols (std::cout).
Q32 • 2 Marks What is a Candidate Key?

Model Answer: In object-oriented data modeling and relational databases, a **Candidate Key** is a minimal superkey—a minimal set of one or more attributes that uniquely identifies every entity or object instance within an entity set without containing redundant attributes.

Q33 • 2 Marks What is information hiding?

Model Answer: Information Hiding is the software design principle of segregating design decisions that are likely to change behind stable interfaces. It prevents client modules from depending on volatile internal representations, allowing internal algorithms and data structures to change without breaking external dependents.

Q34 • 2 Marks Define Object identity with example.

Model Answer: Object Identity is the property of an object that distinguishes it from all other objects regardless of attribute value equality, established by its unique physical memory address.

Example: Two `Account` objects `acc1` and `acc2` residing at addresses `0x7ffee1` and `0x7ffee8` have distinct identities even if both contain identical balance `$500.00`.

Q35 • 2 Marks Define and Differentiate Generalization and Inheritance with example.
  • Generalization (Design Concept): The conceptual taxonomic relationship in UML models discovering common abstractions across subclasses (e.g. `Vehicle` generalizes `Car`).
  • Inheritance (Implementation Mechanism): The physical coding construct in OOP languages enabling a derived class to inherit code and data from a base class (`class Car : public Vehicle`).
Q36 • 2 Marks How is multiple inheritance different and modelled by using nested generalization?
  • Multiple Inheritance: A class inherits directly from two or more base classes (`class C : public A, public B`), risking diamond ambiguity.
  • Nested Generalization (Multilevel): Specialization proceeds in a linear chain (`A` $\rightarrow$ `B : public A` $\rightarrow$ `C : public B`), organizing specialization into distinct, unambiguous hierarchical layers.
Q37 • 2 Marks Write a program to demonstrate all the keywords used in Exception Handling. 
#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0.0) throw std::runtime_error("Division by Zero!"); // 1. throw
    return a / b;
}

int main() {
    try { // 2. try
        std::cout << divide(10.0, 0.0) << "\n";
    } catch (const std::exception& e) { // 3. catch
        std::cerr << "Caught Exception: " << e.what() << "\n";
    }
    return 0;
}
